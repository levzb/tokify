- В Chromium проверены воспроизведение настоящих песен, следующая песня, пробел для паузы, очередь, смена перехода, сохранение текущей песни после перезагрузки.
- **JavaScript в Chromium остановлен через отладчик на шесть секунд во время перехода. Аудио продолжило идти через границу песен.** Это проверка непрерывного потока, а не имитация блокировки iOS.
- В настольном WebKit с параметрами iPhone 13 проверены запуск касанием, мини-плеер, полный плеер и отсутствие горизонтального переполнения. Скриншоты сделаны на 1440×1000 и 390×844 CSS-пикселей.
- `npm run build` проходит без предупреждений Svelte. Дизайн сохранён; dyke.win проверен по живой странице и `design.css?v32`.
- Реальный основной импорт возобновился после перезапуска сервера при внесении исправлений.

Кнопка повтора у каждой песни проверена в Chromium и WebKit с размером iPhone: запуск выбранного трека по кругу, все три режима перехода, отключение повтора, выбор другой песни и восстановление после перезагрузки. Три серверных теста проверяют декодированное аудио повторов одного и того же трека. Также проверено, что рамка первой иконки плейлиста помещается в область прокрутки. Повторная проверка: `npm run test:repeat`.

## Как устроено воспроизведение

Сервер представляет очередь как один непрерывный MP3 с фиксированным битрейтом. Аудио, затухания и наложение смешиваются на Mac заранее для каждого запрошенного участка. iPhone получает обычный аудиофайл с поддержкой перемотки; границы песен не требуют запуска нового HTML audio или работы JavaScript-таймера.

Для экрана блокировки и наушников подключён Media Session API: play, pause, nexttrack, previoustrack и seekto, название и обложка. Обработчики повторно устанавливаются после начала воспроизведения. Для использования этих возможностей нужен HTTPS и проверка на конкретной версии iOS. [Описание Media Session](https://github.com/w3c/mediasession/blob/main/README.md).

## Что не проверено или ограничено

1. **Настоящий iPhone, блокировка экрана, наушники и запуск с экрана «Домой» не проверены.** В этой среде нет подключённого телефона и iOS Simulator. WebKit и остановка JavaScript на компьютере эту проверку не заменяют.
2. При глубоком приостановлении страницы iOS музыка и встроенные переходы рассчитаны на продолжение, но обновление названия/обложки и реакция медиакнопок могут зависеть от возобновления JavaScript. Динамическую смену метаданных на заблокированном экране нельзя считать подтверждённой.
3. Повтор заранее разворачивается в конечный поток: до примерно двух часов / 400 копий для одной песни, до примерно четырёх часов / 1500 элементов для плейлиста (цикл плейлиста может увеличить итоговое число). При активном JavaScript поток затем создаётся снова. Бесконечный повтор при полностью приостановленной странице не гарантирован.
4. Сервер должен работать на бодрствующем Mac, телефон должен иметь доступ к нему. Сон Mac, закрытие крышки или обрыв сети могут остановить воспроизведение. Это не офлайн-плеер; музыка не копируется целиком в память iPhone.
5. Смена очереди или типа перехода создаёт новый поток с текущего места. В момент такой правки возможна короткая буферизация. Обычные переходы внутри уже созданного потока этого не требуют.
6. Удалённые/регионально недоступные звуки, ограничения TikTok и CAPTCHA могут помешать загрузке. Приложение сохраняет ошибку и позволяет повторить попытку; оно не обещает скачать то, что TikTok не отдаёт.
7. Если аудио доступно, но обложку TikTok скачать не удалось, песня играет со стандартной заглушкой. Можно поставить свою обложку.
8. Экспорт обычно содержит только ссылку и дату. До скачивания название неизвестно; для ручного выбора показываются дата и ID. У окончательно удалённого звука настоящее название может так и не появиться.
9. Tailscale и HTTPS-доступ с телефона не настроены: на Mac пока нет Tailscale, а подключение к вашему аккаунту требует вашего входа. Инструкция есть в README.
10. Импорт всего архива запущен, но его окончательный результат нужно смотреть после завершения обработки. Уже проверено реальное скачивание и сохранение ошибок; 967 успешных скачиваний не обещаются.

## Проверка на вашем iPhone

Откройте приватный HTTPS-адрес из README сначала в Safari, затем с иконки на экране «Домой».

- Выберите плейлист минимум из трёх готовых звуков и запустите первый. Заблокируйте телефон дольше, чем длительность первых двух песен. Повторите для Direct, Fade и Crossfade.
- На экране блокировки проверьте паузу/продолжение, следующую и предыдущую песню, название и обложку. Повторите действия кнопками наушников.
- Проверьте то же после переключения на другое приложение, через Wi-Fi и мобильную сеть с включённым Tailscale.
- Закройте приложение, откройте снова и проверьте сохранённое место. Воспроизведение после открытия возобновляется по вашему нажатию, с учётом ограничений автозапуска Safari.

Если один из сценариев не проходит, запишите модель iPhone, версию iOS, Safari или экран «Домой», режим перехода и точное действие. Только после этой проверки можно подтвердить основной сценарий iOS для вашего устройства.

## Импорт внешних файлов

`npm test` включает загрузку WAV/MP4, метаданные, дедупликацию, закрепление «Моих файлов», воспроизведение смешанного потока и редактирование внешних песен. Фото, картинка с расширением MP3, повреждённый WAV и MP4 без аудиодорожки отвергаются до создания записи. Проверены отдельный этап сканирования без добавления в библиотеку, подтверждение импорта с изменёнными названием и автором без повторной передачи файла, авторизация доступа к обложке предпросмотра, удаление временных файлов при отмене и истечении срока.

`npm run test:files` проходит в Chromium и WebKit с размером iPhone на временной библиотеке: фото отсекаются без запроса сканирования, видео без аудио получает немедленную ошибку; из смешанного набора остаются только подходящие файлы. В Import files проверено редактирование названия и автора прямо в тексте, без input-полей, затем импорт, воспроизведение, сохранение, отсутствие дубликатов и закрепление «Моих файлов». Прежний разбор настоящего ZIP TikTok также проверен. Скриншоты `files-*.png` сделаны с тестовыми файлами в отдельной временной библиотеке; тестовые песни в личную библиотеку не добавлялись.


## Поиск и скачивание по ссылке TikTok

- Новая строка над загрузкой на главной использует `.og-search` с dyke.win: Inter, фон 4% белого, рамка, капсула, светлеющий фокус; результат показывается сразу под строкой.
- Проверены обычные видео, звуки, мобильные страницы, короткие ссылки и текст из «Поделиться»; профили, посторонние хосты, порты и учётные данные в URL отклоняются. Навигация серверного Chromium ограничена доменами TikTok.
- Из реальной ссылки на видео получены метаданные, скачаны аудио и обложка, аудио проанализировано ffmpeg. Живая проверка проходила в отдельной временной библиотеке, которая после проверки удалена.
- Изолированные backend-тесты проверяют поиск без скачивания аудио, импорт по нажатию, общий плейлист внешних файлов, сохранение происхождения TikTok, повторное использование аудио и видимые ошибки. `npm test`: 30 тестов проходят.
- `npm run test:links`: Chromium на компьютере и WebKit с экраном iPhone проходят поиск, Download, Open, отсутствие повторного скачивания, обработку неверных ссылок и устаревших ответов; снимки находятся в `screenshots/link-*.png`. Это эмуляция экрана, не проверка на физическом iPhone.


### Редактирование названия и автора через ⋯

- Rename song и Edit author доступны у всех песен, включая TikTok по ссылке и из архива. Используются те же диалоги, что у файлов.
- Пользовательские значения сохраняются отдельными переопределениями; повторное скачивание не заменяет их метаданными TikTok. Пустой автор также сохраняется.
- Backend проверяет редактирование, пустое название, неверный тип, перезапуск и повторный импорт. Изолированный тест удаляет только проверочное аудио и скачивает его повторно, проверяя сохранность пользовательских значений.
- Chromium и WebKit проверяют правки через меню во время воспроизведения, обновление плеера и сохранение после перезагрузки. Снимки: `screenshots/song-menu-desktop.png`, `screenshots/song-menu-iphone.png`.


## Офлайн-аудио для iPhone

- Экспорт всей библиотеки, плейлиста или отдельной песни: один непрерывный MP3 с выбранными переходами либо ZIP с отдельными MP3, тегами и обложками, M3U8 и отчётом. По умолчанию порядок сохранён, перемешивание включается отдельно.
- В подготовке нет сетевых запросов. Непрерывное аудио создаётся тем же рендерером, что онлайн-плеер; файлы содержат главы. Проверены Direct, Fade и Crossfade, длительность и число глав через ffprobe.
- ZIP собирается потоково через fflate с корректным UTF-8, включая кириллицу и emoji; без зависимости от системного zip. Ограничение 4 ГБ сообщается ошибкой, а не повреждённым архивом.
- Проверены исключённые недоступные треки, отсутствие повторов между выгрузками, повторное использование подготовленного файла, инвалидирование кэша после правки метаданных, сохранность готовых заданий после перезапуска, пароль, HTTP Range и HEAD.
- `npm run test:downloads`: Chromium и WebKit с экраном iPhone скачивают файлы через интерфейс и проигрывают сохранённый MP3 при полностью отключённой сети. Проверены переход за границу первого трека и перемотка. Снимки: `screenshots/download-config-*.png`, `screenshots/download-ready-*.png`.
- Офлайн-PWA, поведение приложения «Файлы», AirDrop и заблокированный физический iPhone здесь не проверялись. Сайт по-прежнему требует доступного Mac; офлайн-результат — файлы на устройстве.


## Локальная работа на Mac без интернета

- `npm run offline` и Finder-лаунчер `Start Tokify.command` используют установленный Node и готовую сборку, запускают сервер в фоне и открывают localhost. Уже запущенный сервер не перезапускается, пакетный менеджер и внешняя сеть не используются.
- `npm run test:offline`: Chromium и WebKit на компьютере, `navigator.onLine=false`, все внешние URL заблокированы. Проверяются новые плейлисты, переименование, массовое добавление песен, перетаскивание порядка, удаление принадлежности, правка метаданных и воспроизведение. Изменения проверяются после перезагрузки браузера и полного перезапуска сервера.
- Снимки: `screenshots/offline-organize-chromium.png`, `screenshots/offline-organize-safari.png`. Библиотека, аудио и пароль теста изолированы во временной папке.


## YouTube, SoundCloud и Spotify в общей строке

- Строка принимает ссылки TikTok, YouTube, SoundCloud и Spotify, показывает источник и использует тот же внешний плейлист «Мои файлы». Новые идентификаторы yt-… и sc-… принимаются плейлистами и плеером, метаданные можно редактировать, уже скачанное не загружается повторно.
- yt-dlp установлен в игнорируемом `data/tools/yt-dlp`; есть `npm run setup:media`. Запуск без shell, фиксированные аргументы, разрешённые хосты, лимиты времени и размера, 45 минут на трек. Предпросмотр и скачивание раздельные. Live, DRM, недоступные закрытые источники и явно отмеченные превью отклоняются. Длительность скачанного аудио дополнительно проверяется на усечённую запись.
- Живые проверки в удаляемых временных библиотеках: YouTube «Me at the zoo» и SoundCloud «Flickermood» скачаны целиком с обложками; Spotify «Cut To The Feeling» вернул метаданные и четыре варианта YouTube. Один отдельный запрос YouTube завершился по тайм-ауту, последующая проверка прошла — доступность зависит от сети и ограничений площадки.
- Spotify не скачивается напрямую и не подменяется превью: кнопка Find on YouTube показывает варианты, Choose переводит к явно указанному источнику YouTube.
- `npm run test:media`: Chromium и WebKit с экраном iPhone, тестовые ответы внешних сервисов, общий плейлист, выбор Spotify → YouTube, отсутствие скачивания до нажатия, отбрасывание превью, новые ID в плейлистах, сортировка и непрерывный аудиопоток. `npm run test:links` проходит регрессию TikTok. Снимки: `screenshots/media-*.png`.


## Редактор отрывка

- ⋯ → Trim audio у всех скачанных источников; Import / Import & trim в результатах поиска, Trim audio у уже добавленного результата. Spotify использует выбранный источник YouTube.
- Дорожка из реальных пиков аудио, две границы с перетаскиванием и клавиатурой, точные секунды, увеличение выбранного участка, прослушивание по кругу, отмена и восстановление оригинала. Предпрослушивание останавливает обычный плеер.
- Недеструктивная модель: исходный файл не меняется; base_trim_start/base_samples сохраняют полный диапазон, clip_start/clip_end — выбор. Плеер и экспорт используют effective trim_start/samples. Правки глобальны для песни во всех плейлистах; версия предотвращает перезапись изменений другого окна.
- Backend-тест проверяет исходный файл по SHA-256, расширение за пределы прежней обрезки, восстановление, приватность, Range/HEAD и сохранность после перезапуска. Реально отрендерированный отрывок проверяется по частоте: выбранные 880 Гц вместо исходных 220 Гц. Повторное скачивание YouTube сохраняет диапазон.
- npm run test:clips: Chromium и WebKit с экраном iPhone, ввод границ, перетаскивание, клавиатура, недопустимый диапазон, zoom, цикл предпрослушивания, отмена, сохранение, новый диапазон в плеере, расширение, перезагрузка, сброс и Import & trim. Снимки: screenshots/clip-editor-desktop.png и screenshots/clip-editor-iphone.png. На физическом телефоне не проверялось.
